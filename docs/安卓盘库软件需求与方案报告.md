# 安卓盘库软件：0.2.0 需求与实现说明

日期：2026年10月11日  
应用版本：0.2.0  
使用场景：本人携带一部安卓手机，在任意国家、不同仓库进行离线盘点。

## 一、当前范围

盘库助手是一部手机使用的离线安卓 App。启动先选择或建立国家和仓库，再分别录入配件、整机；数据保存在手机，可导出 Excel、CSV ZIP 和可恢复的完整 JSON 备份。要求 Android 8.0 或以上，不需要账号或服务器。

0.2.0 按新的操作要求取消日常界面的任务、库位，简化为“国家 → 仓库 → 记录”。仓库成为日常查询、统计、清空和导出的边界；历史记录按当前仓库共同展示和汇总。旧任务、库位字段仅保留在数据库和完整备份中，保证已有数据兼容。

编号扫描直接识别标签上的数字、英文字母和 SN 横线，识别后可修改并确认。条形码、二维码内容尚未明确，暂不解析。扫描不会自动清点货物数量或保存记录。

## 二、已确认功能

| 项目 | 0.2.0 行为 |
| --- | --- |
| 国家和仓库 | 任意国家，支持多个仓库；启动页和设置页选择、新建，设置页修改当前名称 |
| 配件 | BOM＋本次数量，以件计，状态和备注放在更多弹窗 |
| 整机 | BOM＋SN，每台一条，数量固定为 1；SN 手动前后两段输入，中间自动加横线 |
| BOM | 1～14 个英文字母或数字，按文本保存 |
| SN | 两段英文字母或数字，左右都非空；不计横线最多 14 位，含横线最多 15 位 |
| 连续录入 | 整机可开启保留 BOM，保存后清空 SN；切换仓库后重新确认 |
| 编号识别 | 相机识别印刷文字，支持纯数字、字母数字混合和横线；候选值需确认 |
| 状态 | 正常、损坏、待核查；只有正常和损坏计入已确认数量 |
| 记录管理 | 正常/作废独立页签；搜索、筛选、修改、作废、还原、永久删除和按仓清空 |
| 导出 | 当前仓库全部历史有效记录，Excel 五页、CSV 三份明细；不含任务、库位列 |
| 完整备份 | 所有国家、仓库、现存记录及修改历史，保留旧版兼容字段 |
| 离线 | 本地 SQLite 保存，OCR 模型随包，不声明联网权限 |

配件统一以件计。箱、包等包装应先换算为件。当前数量表示已盘数量；没有账面库存导入时，不计算盘盈、盘亏或完成率。

## 三、页面与现场流程

启动流程为“选择/创建国家 → 选择/创建仓库 → 进入仓库”。主界面底部只有盘点、记录、导出、设置四页，三个业务页顶部一行显示国家/仓库。国家和仓库选择管理集中于启动及设置，避免在连续录入中展开管理内容。

盘点页固定排布，不上下滚动。配件显示 BOM 和数量；整机显示 BOM、SN 前段、SN 后段及扫描入口。状态和备注在“更多”弹窗中，保留 BOM 通过明确开关控制。键盘出现时收紧布局、保留输入与保存；收起键盘后操作次要控件。

每次保存前检查国家/仓库，输入或扫描并核对编号，填写数量，按需选择状态、备注，最后点保存。数据库写入成功才提示成功并处理输入框。切换仓库前，如有未保存内容，先提示是否放弃；“清空”输入框不影响已保存记录。

同仓库、相同 BOM、相同状态的配件再次录入会提醒追加数量。比如 10 件加 5 件汇总 15 件；纠正原来的 10 件应修改原记录，不能再追加修正后的数量。

## 四、编号、重复与待核查

BOM 规则为 `[A-Za-z0-9]{1,14}`。SN 为恰好一条英文半角横线连接的两段英文字母或数字，两段合计不超过 14 位。手动输入分成两栏，软件补齐横线；扫描完整 SN 后自动分到两栏。

例如 `ABCDEFG-1234567`，不计横线 14 位，应允许；`ABCDEFGH-1234567` 不计横线 15 位，应拦截。编号原样保存前导零和大小写，不自动把 `O` 改成 `0` 或把 `I` 改成 `1`。

完全相同的非空整机 SN 在所有国家和仓库的非作废记录中唯一，包括已填写 SN 的待核查记录。相同 SN 搭配不同 BOM 也不能再次保存。只差大小写时先提示核对，按标签原样保留，不自动合并。

待核查可缺 BOM 或 SN，但至少有一个编号或一条备注；填写的编号仍须符合格式，配件数量仍是正整数。待核查记录在正常页可筛选，导出单列，不计已确认数量。核实后修改原条，补齐编号并将状态改为正常或损坏。

扫描流程为“扫描 BOM/SN → 对准目标区域 → 识别 → 选择/编辑候选 → 确认填入 → 保存”。多个候选由人选择，不把日期、订单号自动当编号；对空格、不同横线等修正展示原文与结果。摄像头持续对准相同标签不会新增记录或累计数量。BOM/SN 各自保留手动或 OCR 来源、识别原文；图像默认不永久保存。

## 五、正常、作废及永久删除

“记录”的正常页包括全部非作废记录，货物状态可以是正常、损坏或待核查。“作废”是独立页签，允许保留重复 SN。搜索支持 BOM、SN 和备注，筛选支持全部、配件、整机、待核查。

修改保留前后历史。作废记录退出数量统计，仍保留数据和历史，整机 SN 可被重新录入。单条还原恢复原状态和数量；如 SN 被另一条非作废整机占用，则保持作废并显示冲突，不覆盖已有记录。

| 操作 | 确认要求 | 范围及结果 |
| --- | --- | --- |
| 单条永久删除 | 1 次 | 删除选中的作废记录及相关审计，不能在作废页还原 |
| 清除全部作废 | 1 次 | 当前仓库全部作废记录及相关审计 |
| 清空正常 | 2 次 | 当前仓库全部非作废记录及相关审计，含全部类别以及正常、损坏、待核查 |

批量清空覆盖当前页全部记录，不受搜索或筛选影响，只作用于当前仓库。清空正常保留作废；清除作废保留正常。永久删除移除相关修改历史，新备份不再含这些记录；以前导出的备份可能仍有，导入旧备份可能重新恢复。

## 六、日常导出与完整备份

日常 Excel/CSV 的范围固定为当前仓库全部历史有效记录。历史任务不再参与筛选、分组，文件中不出现任务、库位列。配件汇总按仓库、BOM、状态合并，国家随仓库显示；正常和损坏分别汇总，待核查不混入确认数量，作废不进入日常导出。

| Excel 工作表 | 内容 |
| --- | --- |
| 盘点说明 | 导出时间、国家/仓库范围、统计规则、编号及 CSV 导入说明 |
| 配件明细 | 国家、仓库、BOM、数量、单位、状态、备注、编号来源及识别原文、创建/修改时间、记录 ID |
| 配件汇总 | 国家、仓库、BOM、数量、单位、状态、录入条数 |
| 整机明细 | 国家、仓库、BOM、SN、数量 1、状态、备注、编号来源及识别原文、创建/修改时间、记录 ID |
| 待核查 | 配件和整机的完整相应字段，单独标明类型，不计入已确认数量 |

Excel 的 BOM、SN 写为文本单元格，前导零、长数字不会转为数值；数量为数值。备注等内容作为文本，不解释为公式。导出时间带时区偏移。

CSV ZIP 包含配件明细、整机明细、待核查三份 UTF-8 BOM CSV 及导入说明，自由文本做公式注入防护。CSV 本身不能锁定文本类型，在 Excel 导入时须把 BOM/SN 列设为文本；优先使用 XLSX。

完整 JSON 备份范围为所有国家、所有仓库，包含现存记录（含待核查、作废）及修改历史，保留旧任务、库位字段。备份格式仍为版本 1，与旧版兼容；有 32 MiB 上限、严格字段类型及 SHA256 完整性验证。校验不等于加密。已永久删除的记录及历史不会出现在新备份中。

通过安卓系统文件选择器保存文件。导出准备快照会先在本机临时保存，以便系统文件选择器期间界面重建后继续导出。日常导出文件用于分析，完整 JSON 用于恢复；每天收工都应复制到电脑或其他位置，手机内保存不等于异地备份。

## 七、0.1.0 升级与旧备份恢复

0.2.0 与 0.1.0 使用同一应用标识和签名，直接覆盖安装，保留数据，升级前建议先备份，不能先卸载。交付 APK 为 `artifacts/盘库助手-0.2.0.apk`，源码为同版本 ZIP。

数据库升级到 schema 3 时，会检查旧任务中允许重复保存的非作废 SN。每个完全相同的 SN 保留最近修改的一条为非作废，其余自动作废，写入包含完整前后记录的 VOID 审计，界面提示处理数量。记录不被永久删除，可到作废页核查。

通过“从备份合并恢复”导入文件时，先验证文件和内容，确认后事务合并。相同记录不重复增加；同 ID 不同内容、与现有数据的 SN 冲突或备份内部重复非作废 SN 会拒绝整个合并，原有数据不变。普通旧备份不会自动使用升级的重复作废规则，应在原设备核查重复项后重新备份。较旧版本与当前记录发生内容冲突时，不提供强制覆盖。

## 八、实现与交付边界

使用 Kotlin、Jetpack Compose、SQLiteOpenHelper、CameraX 和随包 ML Kit 拉丁文字识别。保存、修改、恢复和批量清理使用本地数据库事务；SN 全库唯一由业务检查与数据库索引共同约束。记录及审计保存在手机，不依赖后端、账号或联网运行。

交付包括 0.2.0 APK、同版本源代码 ZIP、操作说明、界面设计说明及验收记录。构建与签名方法见项目 README；签名密钥不包含在源码 ZIP 中，后续升级需要保持相同签名。

真实手机相机和真实标签尚未完成现场验证。识别模型支持离线不代表现场识别准确率已经验证；反光、磨损、小字体和易混字符需要用目标手机逐项试扫。相机权限拒绝时仍可手动输入。

当前范围不包含多人同步、账面库存差异对比、BOM 名称对照表或条码/二维码解析。后续是否增加应由现场需求决定，不改变当前一部手机离线盘点的基本流程。

## 九、验证清单

以下是应覆盖的行为，实际执行结果以验收记录为准：

| 场景 | 预期结果 |
| --- | --- |
| 任意国家建立多个仓库、切换仓库 | 归属清楚，业务页顶部上下文正确，未保存输入先处理 |
| 同 BOM 分两笔录入、修改其中一笔 | 明细保留原笔，汇总正确；跨旧任务同仓记录合并 |
| 前导零、14 位 BOM、SN 两段合计 14 位 | 保存和导出原样，合法边界通过，超限拦截 |
| 同 SN 在另一国家或仓库再次录入 | 全库阻止重复；只差大小写先提醒 |
| 正常、损坏、待核查、作废 | 正常页含前三种，作废独立；确认数量和导出范围一致 |
| 作废后 SN 被重用，再还原原记录 | 还原冲突，原条仍作废，已有记录不被覆盖 |
| 搜索或筛选后批量清空 | 仍清空当前仓对应页全部类别和状态；其他仓保留 |
| 单删、清除作废、清空正常 | 分别一次、一次、两次确认，相关审计随永久删除清除 |
| 0.1.0 同签名覆盖升级 | 数据保留，历史重复 SN 留最新一条，其他作废且有审计和提示 |
| 普通旧备份内部有重复非作废 SN | 整包拒绝，原有数据库不变 |
| 备份完整回读、重复导入、损坏文件、冲突文件 | 兼容旧字段、不重复计数、错误时事务不改变现有数据 |
| 文件选择器期间界面重建 | 导出继续使用准备时快照，成功后清理临时请求 |
| 飞行模式、相机拒绝、模糊标签 | 离线录入/导出可用；可返回手动，错误不自动保存 |
| 固定录入页、键盘、窄屏、字体放大 | 输入及保存可操作，更多与次要控件可在收起键盘后操作 |

出发前应使用真实手机和经人工核对的典型标签，覆盖纯数字、混合编号、最长 SN、前导零、反光、磨损及多编号标签，完成一次“盘点 → 导出 → 备份回读 → 对数”。
