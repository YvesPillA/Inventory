## 工具与检查

需要 JDK 17、Android SDK 35、Build Tools 34.0.0。项目固定 Gradle 8.9、AGP 8.7.3、Kotlin 2.0.21。

Windows 可先运行 `tools/setup-android.ps1`、`tools/build.ps1` 安装工作区工具并检查。已配置 JAVA_HOME 和 SDK 时：

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
.\gradlew.bat assembleDebugAndroidTest connectedDebugAndroidTest
```

连接检查需要模拟器或安卓设备。APK 压缩随包原生库，保留全部原有 CPU 架构，安装时由系统解压。`local.properties`、`.toolchain/`、缓存和签名文件均不提交。

## 正式打包

本机 `.signing/fieldstock-customer-release.jks` 保存固定发布密钥，alias 为 `fieldstock`；`.signing/customer-signing.properties` 保存 `storePassword` 和 `keyPassword`，由 Gradle 本地读取。两者都应另行私下备份，不能放进 PR 或源码包。文件名与家里旧版密钥分开，复制回主开发电脑时保留两套签名。

```powershell
.\gradlew.bat assembleRelease
python tools/package.py
```

脚本读取当前版本，核对 APK 元数据、Manifest、发布证书及非调试标志，再生成正式 APK、源码 ZIP 和 SHA256 校验文件。未签名、签名不符或版本陈旧时停止，不覆盖交付文件。

验证正式 APK 的扫描回调时，使用 `.\gradlew.bat assembleReleaseAndroidTest -PtestBuildType=release` 生成匹配 Release 模块的测试包，避免把 Debug 测试包直接配给 Release 安装。测试设备仅使用合成库存。

仅生成源码使用 `python tools/package.py --source-only`；独立测试环境可用 `--test` 打包带明确“测试版”后缀的 Debug APK。正式目录只保留当前 APK、源码包、校验文件和标准模板；旧文件从 Git 历史获取。

## 本地开发入口配置

开发验证值由本机 `.signing/developer.properties` 的 `developerKeySha256` 提供，必须为 64 位小写 SHA256 校验值。Gradle 仅向 BuildConfig 注入校验值；不配置时无法通过开发入口验证。维护者在本地配置，真实密钥及配置内容不进入代码、PR、源码包、说明或日志。发布打包继续排除整个 `.signing` 目录。
