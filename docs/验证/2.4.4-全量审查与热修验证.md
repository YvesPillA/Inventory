# 2.4.4 全量审查与热修验证

2026-10-31。继续更新原热修 PR，versionName **2.4.4**、versionCode **10**、数据库 schema **5**、客户发布签名均保持不变。诊断中的 `revision` 为 `2.4.4-hotfix-audit-20261030`，可区分同版本安装包。

## 审查范围

三个方向分别检查库存与备份、导入导出、盘点界面与扫描；集成检查补充操作排队、生命周期、诊断导出和覆盖安装。检查现有实现和测试，并用合成数据复现问题后修复。用户提供的 Excel、完整备份和模板仅在本机进行兼容检查，未加入提交或源码包。

## 修复内容

| 范围 | 问题与结果 |
| --- | --- |
| 表格导入提交 | 忙碌时连续确认可能将同批数据排队两次。确认立即占用提交状态，结束或失败后释放；实际写入前重新检查导入历史，避免排队期间其他操作已导入同内容。 |
| 备份再次导入 | 已导入记录后来被配件合并、仓库合并或移动后，重新导入原备份可能再次增加数量。保留多个已处理来源状态，完整备份迁移后仍可识别；兼容旧版有效合并归档中的来源。没有已知来源的同 ID 内容冲突仍整批拒绝。 |
| 位置冲突确认 | 同 ID 国家或仓库改名后无法继续、已记住国家映射时漏报新的仓库冲突。现在可确认沿用现有位置名称，重新解析映射后的冲突；数量选项、校验原因及旋转前的选择保留，整行文字可点击。 |
| 历史与恢复点 | 消耗来源记录的合并保留其修改历史；超出归档容量或 JSON 深度限制整批回滚。没有新增或变化的备份不新建恢复点；恢复点按创建顺序保留，避免手机时钟回拨时丢弃最新操作。 |
| 每日备份 | 当天校验过的文件后来损坏，旧缓存仍可能认为正常。再次检查会重新验证并替换损坏备份。 |
| Excel 与 JSON 边界 | 4000 字备注含字面 `_xNNNN_` 时，按解码后文本校验；巨大的数值指数先比较范围，避免展开成巨型整数。UTF-8 BOM 被文件提供方拆成多次短读取时仍可判别 JSON。JSON 及编码在字符串里的来源、审计分别限制嵌套深度为 64，防止递归解析耗尽栈。 |
| 报告与备注往返 | 同一报告记录 ID 在多个工作表或 ZIP 成员中重复时拒绝整批；标准模板仍允许独立重复行。新报告 CSV 增加“备注转义 / Note escaped”列，精确还原安全前缀，支持 4000 字备注；旧版无标记 CSV 保留原文。备注前后空格及换行在写入库存时保留；合并备注超限在确认前提示。 |
| SN 与备注扫描 | SN 只连接横线邻近空白，避免把标签后面的独立单词或数字拼入 SN。备注的实际识别裁剪使用界面显示的大取景框；多行内容可覆盖其上、下区域。 |
| 操作与生命周期 | 等待操作期间保持忙碌状态。关闭旧界面不在主线程等待同步数据库锁，已进入后台的事务结束后再关闭连接；新界面初始化与旧操作共用队列，避免读到未完成的中间状态。 |
| 诊断导出 | 文件结果接收器固定注册在主界面根部，写入由 ViewModel 管理；旋转、重建或关闭开发窗口后返回保存结果仍可写 ZIP。开发会话跨旋转保留、进程重启后锁定；分享使用唯一临时文件并防止重复启动。 |

标准 CSV 六列/七列模板、Excel 工作表布局和 JSON 版本均未更改。新增的报告 CSV 转义列由本次热修识别；旧版应用未实现这列，应使用更新后的应用回导新 CSV，或使用兼容的 Excel/JSON。中英文报告和模板可交叉导入，新增提示均有中文和英文。

## 复现证据

- 未修复的重复确认：原有 4 件，导入 3 件并连续确认，结果变成 10；修复后为 7，只有一条导入历史。
- 原热修 APK 的原生数据库流程：目标 4 件、备份来源 6 件，仓库合并后为 10，再导入原备份变成 16。相同设备用修复包执行，重复导入仍为 10。
- 原热修 APK 在真实 Android 系统保存选择器中旋转屏幕后，诊断 ZIP 为 0 字节。修复包同流程保存出 **23446 字节**的有效 ZIP，包含环境、持久操作日志和应用系统日志，界面显示保存成功。
- 关闭 ViewModel 时后台事务持有数据库锁，旧实现让调用线程等待约 2 秒；修复后关闭立即返回，事务结束后安全关闭数据库。
- 旧 SN 解析会把 `SN: AB-001 XYZ` 或 `SN: AB-001 23` 后面的独立内容拼入编号；修复后保留 SN 与后续内容的边界。
- 备注原文在文件解析后正确，但数据库导入的 `trim()` 丢掉前后空格、换行；新增实际落库检查先复现，再验证中英文报告、标准 CSV 均保留原文。

以上复现日志保存在本机工具目录；公开记录仅含合成例子和验证结论。
